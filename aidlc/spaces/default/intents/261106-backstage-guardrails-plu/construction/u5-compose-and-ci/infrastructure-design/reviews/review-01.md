### Notes on the checks asked for

**1. Consistency with the NFR Design (security-design.md).** I found no contradiction on: the two networks and the one loopback port, `read_only` and writable paths, PostgreSQL `70:70` with `cap_drop ALL` and the written exception, the start command with `cp -R /app/app-static-src/. ... && exec node packages/backend --config ... --config ...`, trace/video/HAR off, `docker compose run --no-deps` without `--rm` (fixed name, inspected, then removed), and `composeArgs`. The only drift is the "Firefox reported once" timing line (finding 1). Checked against the plugin code: `injectConfigIntoStatic` in `@backstage/plugin-app-backend` reads and rewrites only `*.js` files in the static directory, so the claim that the static directory is the only extra writable path holds for that part.

**2. The three open minors.**
- The backend build command and entry point are named but not proven (finding 5).
- The pristine copy is settled: the whole `dist` goes to `/app/node_modules/app/dist`, only `static` is kept as `/app/app-static-src`, and a tmpfs covers `dist/static`. This agrees with the security design and with the plugin's write behavior.
- The stale NFR Design traceability targets are not carried (finding 4). This stage's traceability.json does not contradict the NFR Design body.

**3. The pipeline.** The four new names (`e2e-unit`, `app-image`, `compose-e2e`, `ci-ok`) are not in ci.yml today, and each is listed once. The 23 existing jobs are: `format`, `lint`, `typecheck`, `test`, `repeatability`, `contract`, `image`, `plugin-unit`, `plugin-rules`, `plugin-coverage`, `plugin-contract`, `plugin-build`, `ui-unit`, `ui-coverage`, `ui-contract`, `ui-build`, `ui-checks`, `app-unit`, `app-coverage`, `app-startup`, `app-catalog`, `app-checks`, `app-build`. The description covers them through "`needs` every other job" and the "all existing jobs" row. It does not list them, which is acceptable because the workflow test derives the list. `ci-ok` fails on any `needs` result other than `success`, so skipped and cancelled jobs fail too. The server `image` job and the new `app-image` job do not collide. Top-level `permissions: contents: read` is already present, and the workflow has no `secrets.`, registry login or push. The only throw-away login is the two plugin jobs' `postgres:postgres`, named as the exemption. Time limits: see findings 2 and 3; the budget of 23 minutes against 25 is tight but stated as a planning estimate.

**4. Resource plausibility.** Not verifiable without a Docker run: whether 1 GB holds Backstage plus the tmpfs frontend copy, whether PostgreSQL starts under `70:70` with a read-only root file system and 512 MB, and whether the u1 server stays inside 256 MB as a hard limit (the 256 MB heap limit of its test suite is a different process and does not prove the container). The tmpfs paths for PostgreSQL (`/tmp`, `/var/run/postgresql`) and the `70:70` plan match how the Alpine image works. The design already says the first real run settles these and a written exception is the fallback; that is the right level for this stage.

**5. traceability.json.** All 39 upstream ids have a target, and every target names an element that exists in `cicd-pipeline.md`, `infrastructure-specification.md` or `monitoring-design.md`. No `N/A` is used. One target disagrees with its document: NFR1.4 (finding 3).

**6. Repository conflicts.** There is no `compose.yaml` and no `packages/e2e`, and the root `package.json` has no `compose:*`, `e2e` or `e2e:timing` script, so none of the new names conflict. `.gitignore` has `.env` and no `.env.compose` entry, so the addition is needed. The root `.dockerignore` has no `.env*` entry, so the addition is needed. It already has `**/coverage`, so "coverage if missing" is a no-op, and it excludes `**/*.test.ts` and `**/testing` (the backend's `tsconfig.build.json` excludes the same paths, so the image build is unaffected). The root workspace glob `packages/*` picks up `packages/e2e` automatically. The root `test` script (`backstage-cli repo test`) will run the new package's unit tests, so Playwright specs must not use the `*.test.ts` pattern.
